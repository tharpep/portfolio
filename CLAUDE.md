# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
pnpm dev        # Start dev server with Turbopack
pnpm build      # Production build
pnpm lint       # ESLint
```

No test suite is configured.

## Architecture

**Stack:** Next.js 15 App Router, React 19, TypeScript, Tailwind CSS v4, pnpm. Deployed on Vercel. Branch `dev` is the working branch; `main` is production.

**Path alias:** `@/*` → `src/*`

### Pages

| Route | File |
|---|---|
| `/` | `src/app/page.tsx` |
| `/about` | `src/app/about/page.tsx` |
| `/projects` + `/projects/[slug]` | `src/app/projects/` |
| `/resume` | `src/app/resume/page.tsx` |
| `/photography` + `/photography/[slug]` | `src/app/photography/` |

### Data sources

**Projects** — All project data lives as a static array in `src/lib/getProjects.ts`. To add/edit a project, edit that file. Set `hidden: true` to exclude a project from all listings without deleting it. The home page's Featured Projects come from `getFeaturedProjects()` (slugs listed in display order in that file) and the "View all N projects" count is computed, so don't hardcode project content in `src/app/page.tsx`. Dates are structured (`dates: { start: "2025-08", end: "2025-12" | "present" }`, or `"2024"` for year-only) and formatted by `formatDateRange()` in `src/lib/dates.ts` to match the resume ("Aug – Dec 2025", "Jan 2025 – Present"). Keep descriptions to about 140 characters: cards show three lines, and longer ones trigger a `[projects]` warning in dev and build logs.

**Photography** — Collections are auto-discovered from Cloudinary folders under `photography/`. No hardcoded list. Just upload a folder to Cloudinary and it appears automatically. Manual overrides (camera, location, `featured`) live in `collectionOverrides` in `src/lib/collections.ts`. Collection metadata (title, description, mood) is generated by Claude Haiku (`claude-haiku-4-5-20251001`) via `src/lib/ai-metadata.ts` and cached 24h with `unstable_cache`.

**Spotify** — `src/data/spotify-data.json` is a static file updated daily by the GitHub Actions workflow (`.github/workflows/spotify-sync.yml`), which runs `spotify-scripts/fetch_spotify_data_github.py`. The Next.js app reads this file directly via `src/lib/spotify-data.ts`.

### SEO

- **OG image (dev portfolio)** — `src/app/opengraph-image.tsx` generates a dynamic 1200×630 branded image via `next/og` (edge runtime). No static asset needed.
- **OG images (photography)** — Set per-page in `generateMetadata` using `getCollectionCoverUrl(collection.folder)` (collection pages) or `getCollectionCoverUrl('featured'/'about')` (index/about). Pass the Cloudinary **folder name**, not the URL slug.
- **Sitemap** — `src/app/sitemap.ts` is async and dynamically includes all collection slugs via `getDiscoveredCollectionSlugs()`.
- **Robots** — `src/app/robots.ts` allows all and points to `/sitemap.xml`.
- **Schema.org** — Root layout has `Person` JSON-LD. Each collection page adds an `ImageGallery` JSON-LD via `<Script>`.

### Styling

- **Fonts** — Inter and Geist Mono are self-hosted with `next/font/local` in the root layout (variable-weight latin `.woff2` files in `src/fonts/`, from Fontsource, with their OFL licenses). Their CSS variables are set on `<html>` and mapped to Tailwind's `font-sans` / `font-mono` in the `@theme inline` block in `globals.css`. The photography section adds Bricolage Grotesque the same way via `--font-display`. Don't switch back to `next/font/google`: on some Vercel build machines Google returns font addresses it can't parse, and the build fails.
- **Text styles** — `src/lib/typography.ts` defines one class string per role (`heroTitle`, `pageTitle`, `sectionTitle`, `subTitle`, `cardTitle`, `meta`, `tag`). Use these for headings, dates and tech chips instead of per-page size classes; add only layout classes (margins, alignment) alongside them. Monospace is for page/section headings and data (dates, tech names); card titles and body text are sans.
- **Project cards** — `src/components/ProjectCard.tsx` is the only card, used on home and `/projects`. Its slots are fixed at every width: title → dates · status → description (3 lines, clamped and reserved) → stack (1 line) → links. Don't add `block`/`flex` display classes next to `line-clamp-*`; they cancel the clamp.
- **Home hero portrait** — `public/images/pryce-tharpe.jpg` is an 800×800 square crop (no metadata), shown as a circle whose bottom quarter fades out (`mask-image`) under the H1. Replace the file with another square crop to change the photo.
- **`<ScrollFadeIn>`** renders fully visible on the server; only content that is below the fold after hydration fades in on scroll. Don't reintroduce SSR `opacity-0` wrappers, since they hide above-the-fold content until JS runs.

### Navigation / Layout

Page fades: the root layout wraps the site in `<PageTransitions>` (`src/components/PageTransitions.tsx`), which uses the View Transitions API to fade between pages when a link is clicked; timing and the anchored nav (`site-nav`) are the `::view-transition` rules in `globals.css`. Internal links on the main site must use `import { Link } from "@/components/PageTransitions"`, not `next/link`, or that click jumps without the fade. Back/forward are intentionally not animated so the browser's scroll restoration and iOS swipe-back work. The photography section keeps its own `<ViewTransitions>` provider from `next-view-transitions` (its layout) for its photo morphs, and its pages use that package's `Link`. Don't set `scroll-behavior: smooth` on `html`: it animates scroll restoration on back/forward.

The root layout renders `<ConditionalNav>` and `<ConditionalFooter>`, which suppress themselves on any `/photography` route. The photography section has its own `<PhotoNav>` component and its own layout at `src/app/photography/layout.tsx`. `<PhotoNav>` shows a camera icon (not the name) as the brand/home link to avoid name repetition across sub-pages.

### Environment variables

| Variable | Used by |
|---|---|
| `NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME` | Cloudinary (public) |
| `CLOUDINARY_API_KEY` | Cloudinary server calls |
| `CLOUDINARY_API_SECRET` | Cloudinary server calls |
| `ANTHROPIC_API_KEY` | Photography collection metadata via Claude Haiku |

Spotify secrets (`SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET`, `SPOTIFY_REFRESH_TOKEN`) are only needed for the GitHub Actions workflow, not for running the Next.js app locally.
